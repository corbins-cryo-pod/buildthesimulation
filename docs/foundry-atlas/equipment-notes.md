# Equipment capability audit

**Snapshot:** [BuildTheSimulation source register at commit 83724fc](https://github.com/corbins-cryo-pod/buildthesimulation/tree/83724fcb47c3d6ea6265ad3d09f8fa6157e322f3/src/data/equipment), checked November 28, 2026. All sixteen zone files, the zone definitions and source index were retrieved from that pinned revision and compared byte-for-byte with the working register. Individual SHA-256s are in the JSON.

**Coverage:** 199/199 stable register IDs, all 16 zones, 75 bounded operation groups, 12 explicit classes of unmet or conditional capability. 83 stations implement a bounded task-related model, 55 offer inspection/replay only, 52 are exhibits only, and 9 track support/custody. These are classifications of what can be done with the *station simulator*. They are not the number of real machines in a facility, the number of manufacturing tools, or the number of experimentally validated processes.

## Read the three axes separately

1. **Does a physical instrument of this type perform a relevant operation?** Each operation definition records the proposed role and an evidence gate. A shape-compatible reference can still be unsuitable because of material, feature, wafer size, stack temperature, fixture, or contamination restrictions.
2. **What does this specific virtual station do now?** A named fab process, a rendered cabinet, a link labeled simulator or a proposed acceptance test is not evidence of an implemented operation. Each record has its own software scope and a manually checked limitation. Where the register only said “Built”, the linked simulator was inspected directly (01-05, 03-02, 16-11, 16-14). A bounded model can mean only a geometry decision, signal replay or first-order solver; read its scope, not just its category.
3. **What evidence exists for the selected device and configuration?** Equipment links are candidate classes unless a route source identifies the installation and documents the actual step. A reference/simulator does not make real hardware, prove permission to use the machine, validate a process chain or establish chronic/clinical performance.

## Evidence checks that change routing decisions

- **02-03 maskless writing:** The [Heidelberg Technical Data table](https://heidelberg-instruments.com/product/mla150/) distinguishes Mode II's 1 µm feature and 1.2 µm lines/spaces from Mode I's optional 0.45 µm spec. Only one mode can be installed. Features and dense lines/spaces are not the same limit.
- **02-01 contact exposure:** The [NIST Gen4 installation](https://www.nist.gov/laboratories/tools-instruments/nanofab-tool-suss-microtec-maba6-gen4-mask-aligner) takes pieces through 150 mm wafers. A 200 mm CMOS wafer cannot simply be routed through this implementation as a whole wafer. Even if an approved coupon transfer exists, it is a different process flow and constraint.
- **03-08 parylene:** The [Utah PDS 2010 reference](https://www.nanofab.utah.edu/wp-content/uploads/2022/11/Parylene-Deposition-SOP.pdf) establishes a real coating tool; the site's version implements normal offsets and protected-contact mask inspection, not deposition or barrier acceptance.
- **04-03 DRIE:** A [Manchester Cobra 300 installation](https://research.manchester.ac.uk/en/equipments/oxford-instruments-plasmapro-100-cobra-300-reactive-ion-etcher-ri-2/) specializes in silicon; the [UCSB Cobra 300](https://wiki.nanofab.ucsb.edu/wiki/Oxford_ICP_Etcher_%28PlasmaPro_100_Cobra%29) is a different configuration for III–V epitaxies and related work. The site's six-inch Bosch geometry case is not a general translation to a 200 mm wafer, other materials or a different chamber.
- **04-12 bonding:** [EV Group's EVG501](https://www.evgroup.com/products/bonding/permanent-bonding-systems/evg501) has multiple bond schemes and optional tooling; the [AggieFab installation](https://aggiefab.tamu.edu/equipment/evg-501-wafer-bonder/) describes a compatible separate aligner. Stage fit is not evidence of an aligned seal.
- **09-01/09-12 electrochemistry:** The [Gamry Reference 600+](https://www.gamry.com/support-2/legacy-devices/reference-600plus-legacy) is EIS capable. An ideal passive EIS/CV example and a test-cell model do not implement a production Pt-black, iridium oxide, PEDOT, or other device-specific deposition line.
- **03-02** [thermal evaporation exhibit](https://buildthesimulation.com/simulations/equipment/03-02/simulator/): compare fixed mirror-coupon thickness maps; input time/flux or a new evaporant cannot create an arbitrary film. **04-07** [dicing exhibit](https://buildthesimulation.com/simulations/equipment/04-07/simulator/): an inspected grid is not a separated die or measured kerf.

## Data and tests

`records[].operations` are potential physical tool roles, not claims of software support. Join the keys to `operations` for the operation title, scope and witness gate. Each record also has its exact register name/model, register grade, roles, realization code and label, simulation scope, one or more specific limits, register/simulator links and source IDs. Equipment without public sources is retained and marked by an empty source-ID list, never promoted by default. The 135 source index entries comprise 80 register references, 47 inherited external related links and eight primary-source checks. Entries may share URLs; this is not a claim of 135 unique independently checked publications. Thirty-seven records have no external link in these fields (some may have internal simulator documentation).

The `gaps` list distinguishes a true external module from a neighboring station that looks suitable but does not supply it. `nearbyEquipmentNotEquivalent` must never be used as an approved substitution list.

To regenerate from a checkout of the pinned register, pass the path to its `src/data/equipment` directory and the lane JSON destination explicitly to the build and check scripts in `scripts/foundry-atlas/equipment/`. The curator-reviewed tables in that directory enumerate every stable equipment ID and every operation; a missing/new ID fails the build. Checks pass for exact IDs/names/models/links, all source and role joins, original source digests, dry-only regression cases, the Mode II line/space gate, and a byte-identical rebuild.
